# SOUL — Sequential Pair Integration Contract

## Canonical pair sequence

1. N06 <-> N05
2. N05 <-> N04
3. N04 <-> N03
4. N03 <-> N02
5. N02 <-> N01

The six nuclei remain independent AIs connected through the single canonical Soul Mesh. Engineering optimization follows the adjacent pair sequence while system-wide compatibility is reviewed in parallel.

## Pair completion requirements

Audit both nuclei together for AI role, agents, capabilities, tools, inbound/outbound Mesh, discovery, correlation, authentication, authorization, ownership, fallback, retries/timeouts and complementary delegation.

Existing functionality is reused or repaired before new functionality is added. No second Mesh or duplicate transport is introduced.

The goal is complementary specialization: deterministic bounded work may remain a tool; work requiring independent reasoning may be delegated to the appropriate nucleus. Runtime delegation can use any authorized nucleus according to the CapabilityGraph; the sequence controls engineering order, not runtime reachability.

A pair is structurally closed only when both directions are represented consistently in the shared Mesh contract and the two nuclei's capabilities and agents can compose without naming or ownership mismatches.

Runtime tests are commissioning evidence, not a prerequisite for structural implementation. When execution is unavailable, structural readiness and live commissioning status remain separate.
